# Decision Log

## DL001 2026-08-06 軽量な decision log を採用する

**やる**: 意志決定の記録を `docs/decision.ja.md` に日本語で 1 エントリずつ追記する。形式は `## yyyy-mm-dd タイトル` の下に **やる** / **やらない** / **なぜ** の 3 項目。長さは自由で、1 行でもよい。既存エントリへは誤字脱字の修正など情報量を増やさない変更を認め、補足情報は追記の形で加えてよい。追記には `（追記 yyyy-mm-dd）` のように日付を付ける。決定を覆すもの、情報の追加によってスコープが変わるものなど、行動が変わる変更は新しいエントリとして書く。

**やらない**: フルの ADR 駆動開発（1 決定 1 ファイル、Context/Decision/Consequences、Status 遷移などの様式）は採らない。このファイルを英語では書かない。decision logを作業記録として扱わない。

**なぜ**: 実験的なプロジェクトの柔軟さと ADR 駆動開発の規律のバランスを取りたい。様式を重くするとドキュメントが肥大化し、AI にしか読めないものになってしまう。メインの開発者が読み書きしやすい言語を使うことで、プロジェクト初期に人間が細かく介入する余地を増やす（初期段階を超えたら英語にする可能性はある）。

(追記: 2026-08-11) DL008でタイトルの形式は `## DLnnn yyyy-mm-dd タイトル` と変更された
(追記: 2026-08-15) decision logのあり方を追記した。単に行ったこと、細かい決定を書くことが目的ではなく、ADRのように、プロジェクトとしての意思決定、今後の開発に影響を与える意思決定、他に有力な選択肢があった上で行った意思決定を記録することが目的。

## DL003 2026-08-06 スキル・コード・ドキュメントは原則英語で書く

**やる**: スキル本体、コード、ドキュメントは原則として英語で書く。英語でないファイルは `decision.ja.md` や `docs/ja/intro.md` のように、ファイル名またはパスに言語を含める。

**やらない**: 英語以外のファイルを言語の指定なしに置くことはしない。

**なぜ**: 英語のほうがより広いユーザーにリーチできる。またプロジェクトの性質上、これらを読むのは主に AI である。

## DL005 2026-08-06 回路は Qiskit で組んで QASM3 に変換する

**やる**: Qiskit で回路を構成し `qasm3.dumps()` で QASM3 に変換して投入する。qiskit を入れられない環境向けに QASM3 直書きのフォールバックも残す。

**やらない**: QASM3 直書きや quri-parts を主経路にしない。無駄なトランスパイルをクライアント側でやらない。(サーバーでのトランスパイルに不備がある、トランスパイラ自体の研究開発である場合など、クライアントでのトランスパイルが必要な場合は行ってもよい)

**なぜ**: 学習データが多く LLM の生成精度が高い。人間の可読性も高い。構文エラーが Python 例外として即座に返るため自己修正の効率が桁違いによい。トランスパイルはサーバー側で行った方が効率がいいと期待できる。

## DL007 2026-08-11 最初の SKILL.md はジョブ管理に絞る

**やる**: デバイス選択、QASM3 でのジョブ投入、ジョブ終了待ち、結果取得、ジョブ一覧を扱う。認証規約（config.ini を読まない、トークン管理 API を呼ばない）も併せて書く。

**やらない**: 量子回路の書き方の指南はしない（「QASM3 を直接書く」か「Qiskit で組んで `qasm3.dumps()`」の提示までで止める）。SSE、バッチ並列、estimation の詳細は今は書かない。セットアップの自動化も行わない（ユーザー自身にトークンを書かせる案内までで止める）。

**なぜ**: ジョブ管理が OQTOPUS ならではの部分であり、汎用の LLM 知識で代替できない。回路の書き方は LLM がすでに得意で、書くと分量が増えるだけで精度は上がらない。SSE / バッチ / estimation は実地動作が未確認（getting-started-memo.ja.md §9）で、書けば嘘を含むリスクがある。

**補足**: `wait` / `run_job` の `failure_statuses` 引数は実装上無視されている（`services/client.py:856` が `_ = failure_statuses`）。FAILED は常に terminal 扱いで正常 return するため、「例外が出なければ成功」という前提が誤りであることが確定した。SKILL.md では実装の詳細ではなく挙動（必ず `result.status` を見る）として書いた。

(追記: 2026-08-15) 認証規約にあった「config を print しない」を取り下げた。oqtopus-clientのバージョンアップで `repr` にトークンが表示されなくなり不要となった。
